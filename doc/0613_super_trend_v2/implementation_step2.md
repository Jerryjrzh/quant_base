## 一、当前系统里，这两套逻辑各在哪、各管什么

| 维度 | 形态判断 | 压力/支撑判断 |
|------|---------|-------------|
| **在哪实现** | `feature_extractor_v2.py`（均线束、洗盘、排名序列等V2特征） | `market_structure.py`（Swing点、POC、关键价位） |
| **干什么用** | 作为**模型输入特征**，让LightGBM学习“什么形态容易出牛股” | 作为**入场/出场决策依据**，决定“现在能不能买、在哪止损止盈” |
| **在哪个环节生效** | 选股阶段：模型打分 → 精排Top 20 | 执行阶段：结构过滤 → 等待回调 → 入场/出场 |
| **验证了吗** | ✅ 已验证：V2特征重要性Top 10占8席，精排模型孪生对100%区分 | ✅ 已验证：结构化回测平均盈亏转正，过滤器有效拦截下降趋势 |
| **验证的是什么** | **选股能力**：模型能否从截面相似的股票中挑出未来涨幅更大的 | **入场质量**：在支撑位买入、结构止损止盈能否把选股信号转化为正收益 |

**两条线各自验证有效，但从未合在一起验证过。**

## 二、碎片化带来的盲区

1. **形态特征和压力支撑之间是什么关系？**
   - 模型选出一只股票，可能因为它有“均线束粘合后发散”的形态。
   - 但执行端在判断支撑位时，用的完全是另一套逻辑（Swing点、POC），和形态特征无关。
   - 一个“均线束粘合”的股票，它的支撑位是Swing点？还是均线束本身的下沿？当前系统不回答这个问题。

2. **形态判断中的“洗盘”和压力支撑判断中的“支撑位”是不是同一个东西？**
   - V2特征里有`washout_ma60_flag`（破位MA60后收回），这是形态判断的“洗盘”。
   - 如果这只股票在信号触发后回踩MA60，系统会认为这是一个支撑位（因为MA60在`get_key_levels`里）。
   - 但系统**不会因为“这只股票的V2特征显示它经历过洗盘”而对这个支撑位赋予更高的权重**。

3. **模型学到的形态信号，执行端完全没有利用。**
   - 精排模型最重要特征`price_rebound_from_pit`（从坑底反弹力度），本质上在描述“这只股票刚从一个支撑位反弹”。
   - 但执行端在判断支撑位时，不会参考这个特征——它只认Swing点和均线，不认“坑”。

**结论：选股端和执行端说的是两种语言。形态判断在选股端起作用，压力支撑在执行端起作用，但它们之间没有桥梁。**

## 三、怎么缝合：让形态判断和压力支撑判断形成闭环

### 3.1 第一步：定义“形态与结构的对应关系”

把V2形态特征翻译成结构语言，让执行端能理解选股端的判断：

| V2形态特征 | 对应的结构含义 | 执行端怎么用 |
|-----------|-------------|------------|
| `ma_glue_max_days>=5` + `ma_glue_recency<=3`（刚粘合后发散） | 均线束的**下沿就是支撑位**（多条均线密集处） | 把这个“均线束支撑”加入`supports`列表，优先级高于普通Swing点 |
| `washout_ma60_flag=1`（破位MA60后收回） | MA60是一个**被验证过的强支撑**（因为刚刚被砸穿又收回） | 对这个MA60支撑赋予更高权重（如ATR缓冲从1.0降到0.5） |
| `price_rebound_from_pit` 排名靠前（从坑底反弹力度大） | “坑”的底部是一个刚被确认的支撑位 | 把“坑底”识别为支撑位，并标记为高置信度 |
| `rs_rank_mean_20d` 排名靠前（持续强于市场） | 趋势强度高，支撑位更可能有效 | 上升趋势中的支撑位置信度加权 |
| `bull_ratio_10d>=0.7`（10天阳线占比高） | 买方主导，回调浅 | 入场时对回踩深度要求放宽（支撑位上方1%即可入场，而非必须触及） |

### 3.2 第二步：在入场判断中融合形态信号

当前入场逻辑只看价格是否触及支撑位。融合后：

```python
def get_fused_supports(structure, v2_features):
    """
    将 market_structure 的计算结果和 V2 形态特征融合，
    生成带权重的支撑位列表。
    """
    fused = []

    # 1. 基础支撑位（来自 market_structure）
    for level in structure.supports:
        confidence = level.tests / 5.0  # 基础置信度
        fused.append(SupportLevel(price=level.price, 
                                   source=level.source,
                                   confidence=confidence))

    # 2. 均线束支撑（来自 V2 形态判断）
    if v2_features.get('ma_glue_max_days', 0) >= 5:
        # 取多条均线的平均值作为"均线束支撑"
        ma_cluster = (structure.ma20 + structure.ma60) / 2  # 简化
        fused.append(SupportLevel(price=ma_cluster, 
                                   source='ma_cluster',
                                   confidence=0.8))  # 高置信度

    # 3. MA60洗盘支撑（来自 V2 形态判断）
    if v2_features.get('washout_ma60_flag', 0) == 1:
        # MA60 刚被砸穿又收回，置信度很高
        fused.append(SupportLevel(price=structure.ma60,
                                   source='ma60_washed',
                                   confidence=0.9))

    # 按置信度排序，高置信度的支撑位优先用于入场判断
    fused.sort(key=lambda x: x.confidence, reverse=True)
    return fused
```

### 3.3 第三步：在止损止盈中利用形态置信度

```python
def set_initial_stop_fused(entry_price, fused_supports, atr):
    """
    根据融合支撑位设置止损。
    高置信度支撑位 → 止损更紧（因为支撑更可靠）
    """
    if not fused_supports:
        return entry_price * 0.95  # 退化

    best_support = fused_supports[0]
    if best_support.confidence >= 0.8:
        buffer = 0.5 * atr  # 高置信度，窄缓冲
    else:
        buffer = 1.0 * atr  # 低置信度，宽缓冲

    return best_support.price - buffer
```

## 五、总结：从碎片化到闭环

```
当前架构（碎片化）：
  选股端: V2形态特征 → 模型打分 → Top 20
           ↓ (信息断裂，形态信号没传下去)
  执行端: 独立计算Swing点/均线 → 等待回调 → 止损止盈

目标架构（闭环）：
  选股端: V2形态特征 → 模型打分 → Top 20
           ↓ (形态信号传递给执行端)
  执行端: 独立计算Swing点/均线 + 接收V2形态信号
           → 融合支撑位（带置信度）
           → 入场判断（优先回踩高置信度支撑）
           → 止损止盈（高置信度支撑用更紧止损）
```

**这个融合是当前最关键的缺失环节。** 选股模型已经学会了识别“洗盘后的MA60支撑很强”，但执行端并不知道这个信息——它只把MA60当作一个普通的支撑位来对待。缝合后，系统才能做到：**“模型认为这只股票结构优秀 → 执行端给它的支撑位更高置信度 → 更窄的止损、更早入场 → 盈亏比提升”。**
