## 一、最致命的问题：数据限制导致验证结论必然失真

计划中明确写道：“60m 数据来自 5min 聚合，仅覆盖 925/4423 信号 (2025-12-15 之后)”。

**这意味着什么？**

| 月份 | 是否在925笔中 | 原日线表现 | 对验证的影响 |
|------|-------------|----------|------------|
| 2025-02~08 | ❌ 不在 | 强势，avg +4%+ | 无法验证小时线在好行情中是否误杀 |
| **2025-09~11** | **❌ 不在** | **弱势，avg -1.64%** | **无法验证小时线对弱势月的改善效果——这是引入小时线的核心动机** |
| 2025-12~2026-01 | ✅ 在 | 强势，avg +4~5% | 只能验证小时线在好行情中的表现 |
| 2026-02~03 | ✅ 在 | 弱势，avg -2~3% | 样本极少（约16笔），统计意义不足 |

**结论**：925笔信号**完全错过了弱势月（09-11月）的数据**，而弱势月恰恰是我们引入小时线最想解决的问题。在这个子集上得到的任何结论——无论好坏——都不能代表全量效果。

**唯一正确的做法**：必须补齐2025-02至2025-12-14期间的60分钟数据。如果5分钟数据只有2025-12-15之后的，可以考虑：
- 用日线数据**模拟60分钟关键特征**（如日内振幅、高低点位置、收盘位置），虽不如真实60分钟精确，但至少覆盖全量信号。
- 或者用1分钟数据聚合（如果有更早期的分钟数据）。
- **如果无法补齐，本次验证只能算“初步探路”，不能作为小时线是否有效的最终判断。**

## 二、“全生命周期”改动范围过大，无法归因

计划要求一次完成四个Phase：入场增强、止损止盈增强、持仓管理增强、被过滤信号救援。改动涉及`structure_entry`、`structure_exit`、`dynamic_exit_manager`三个核心模块。

**问题**：如果最终结果变好，你不知道是入场确认、60分钟止损、还是60分钟动态出场中的哪个贡献了增量。如果变差，你也不知道是哪个环节出了问题。**这种“大杂烩”式的验证无法指导后续迭代。**

**修正**：分阶段验证，每个Phase独立对比基线：

| 阶段 | 验证内容 | 独立对比基线 |
|------|---------|------------|
| Phase 1 | 仅加入60分钟入场确认 | 对比：日线入场 vs 日线入场+60分钟确认 |
| Phase 2 | 仅替换60分钟止损止盈 | 对比：日线止损止盈 vs 60分钟止损止盈（入场逻辑不变） |
| Phase 3 | 仅替换60分钟持仓信号 | 对比：日线动态出场 vs 60分钟动态出场（入场+止损不变） |
| Phase 4 | 被过滤信号救援 | 独立统计可救援信号数量和模拟盈亏 |

**每个Phase验证通过后，再叠加下一个Phase。** 这是量化策略迭代的标准做法，避免“黑箱优化”。

## 三、Phase 4（被过滤信号救援）边际贡献极小，优先级应降低

计划要求对769笔过期信号和183笔被过滤信号进行60分钟救援分析。

**现实评估**：
- 这952笔信号中，有60分钟数据的可能只有约200笔（按20.9%比例估算）。
- 即使60分钟确认能“救回”一部分，这些信号在原日线系统中是负期望的（过期信号Hold -6.23%，被过滤信号Hold -4.58%）。
- 救回的交易大概率只是“从大亏变小亏”，对整体盈亏贡献极小。
- 而且这部分需要大量的路径模拟和人工标注，**投入产出比极低**。

**修正**：Phase 4降为P2优先级。当前精力应聚焦在Phase 1——这是整个小时线增强的入口，如果入场确认本身无效，后面的止损止盈增强就没有意义。

## 四、具体逻辑层面的调整建议

### 4.1 60分钟止损增强（Phase 2）存在逻辑错误

```python
# 计划中的逻辑
swing_low = 入场前 60m 最近 swing low (最近8根60m bar的最低点)
止损 = swing_low - 0.5 * hourly_atr
```

**问题**：入场是在回调到日线支撑位后执行的。入场前的60分钟swing low，**大概率就是日线支撑位本身**（因为价格刚刚从那里反弹）。用这个价格做止损，等于是“在支撑位上设止损”，没有任何缓冲空间。正常的回调波动就会触发止损。

**修正**：
```python
# 60分钟止损应该在日线支撑位下方，而不是入场前的swing low
止损 = 日线支撑位 - 0.5 * hourly_atr  # 在日线支撑下方加缓冲
# 或者
止损 = min(入场前swing_low, 日线支撑位) - 0.5 * hourly_atr  # 取两者中较低者
```

### 4.2 60分钟动态出场信号检测的周期问题

计划中定义：
```python
h_D2: 连续4根60m阴线（等同日线1天）
h_D4: 60m收盘跌破支撑 > 1%（比日线更快触发）
```

**问题**：60分钟K线的噪音远大于日线。连续4根60分钟阴线在A股中非常常见（尤其是在午盘前后），直接作为出场信号会导致**过度交易**。

**修正**：
- `h_D2`改为**连续8根**60分钟阴线（约等于日线1天的有效信息量）。
- `h_D4`改为**连续2根**60分钟收盘跌破支撑>0.5%，且第二根成交量不萎缩（防止假破位）。

### 4.3 小时线企稳确认中“缩量企稳”的条件需量化

计划中提到“缩量企稳 (vol < 0.8x MA20 + 温和阳线)”，但未定义“温和阳线”。

**补充定义**：
- 温和阳线：60分钟涨幅在0.2%~0.8%之间（太弱无意义，太强不是企稳而是反弹）。
- 同时该60分钟K线的下影线 > 上影线（证明买盘在低位承接）。

## 六、最终判断

**这份计划的方向是正确的，但执行顺序和范围需要调整。**

核心问题：
1. **数据覆盖不足**（仅925笔，且错过弱势月）——必须先补齐数据。
2. **改动范围过大**（四个Phase一起上）——必须分阶段独立验证。
3. **止损逻辑有误**（swing_low当止损位）——必须修正。
4. **Phase 4优先级过高**——应降为P2。

**按修正后的计划执行，先聚焦Phase 1（60分钟入场确认），用全量数据验证其有效性。** 这是整个小时线增强方案的基石。如果Phase 1无法证明60分钟确认能显著过滤假回调、提升盈亏，后续的Phase 2-4就没有必要继续。
