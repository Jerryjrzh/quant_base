## Apply8 实施结果诊断：大盘特征成功入模，但回测对比存在逻辑问题

---

### 一、正面发现：大盘特征已被模型主动学习

**这是本次实施最重要的成果。**

| 大盘特征 | 重要性排名 | 重要性分值 |
|---------|-----------|-----------|
| `hs300_ma60_slope` | **第7位** | 5 |
| `hs300_close_ma60_ratio` | **第8位** | 5 |

两个大盘特征双双进入 Top 10，与 `fine_score`、`stock_return_20d`、`ma_dispersion_20d` 等核心个股特征并列。这说明：

- 模型**确实在学习市场环境对信号可操作性的影响**。
- 不需要硬编码“弱势月跳过”规则，模型会自动根据大盘状态调整 `operable_score`。
- AUC 在训练集和验证集上均提升（0.925→0.959，0.899→0.907），模型区分能力增强。

---

### 二、回测对比存在逻辑问题：v1 和 v2 都显示 0 笔交易

报告中 Step 4 显示：

```
v1 (原模型): 0 笔, avg 0.00%, PF 0.00
v2 (大盘感知): 0 笔, avg 0.00%, PF 0.00
```

但同时又显示：

```
thr=0.15: 394 笔, avg 3.64%, PF 2.99, 弱势 45 笔 avg -1.64%
thr=0.18: 394 笔, avg 3.64%, PF 2.99, 弱势 45 笔 avg -1.64%
...
thr=0.25: 361 笔, avg 3.96%, PF 3.25, 弱势 41 笔 avg -1.57%
```

**矛盾点**：如果 v2 在各种阈值下都有交易（361-394 笔），为什么 v1 vs v2 对比行显示 0 笔？

**可能原因**：
1. v1 vs v2 对比使用了不同的回测脚本或参数配置（如 `max_wait_days` 未设、`fine_score` 过滤阈值过高），导致两边都没产生交易。
2. 阈值敏感度测试和 v1/v2 对比是两个独立运行，后者有 bug。
3. v1 模型文件加载失败，导致所有信号都被过滤。

**结果**：`验收标准检查` 中的“弱势月交易数减少”、“弱势月 avg PnL 提升”等指标全部基于 0 笔交易的无效对比，不能采信。

---

### 三、弱势月份识别规则需要校准

报告显示：

```
弱月识别: Precision=0%, Recall=0%, Accuracy=57%
```

但同时逐月表格中，2025-09、10、11 和 2026-02、03 被标注为 `预测弱势: YES`，且这些月份确实在之前回测中表现为弱势（avg PnL 负）。说明规则**实际上识别到了弱势月**，但 Precision/Recall 计算可能用了错误的标签对比（例如用“弱势占比 > 50%”作为标签，而实际弱势月的弱势天数占比并不高——2025-09 为 0%，但实际表现很差）。

**诊断**：
- 2025-09~11：HS300 斜率均为正值（0.242/0.217/0.154），不符合 `close < MA60 AND slope < 0` 的弱势定义，但实际交易表现是负的。
- 这说明**2025 年下半年的弱势不是大盘下跌导致的，而是个股层面的“指数不跌、个股不涨”的结构性分化**。单纯用 HS300 的 MA60 规则无法捕获这种行情。

**需要改进**：增加个股层面的市场宽度指标（如全市场上涨家数占比、强势股占比），而非仅依赖 HS300 指数。
